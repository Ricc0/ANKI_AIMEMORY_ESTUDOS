Regressão, classificação e como medir cada uma

As duas grandes tarefas do supervisionado (Lição 1) se distinguem pelo formato da resposta, e cada uma tem suas métricas. A vitória desta lição é entender por que um modelo com 99% de acurácia (accuracy) pode não servir para nada[1].

Pegadinha: o nome engana A regressão logística é classificação. Ela calcula uma probabilidade com a função sigmoide e aplica um LIMIAR (por exemplo 0,5) para decidir a classe. O nome vem de ser uma regressão sobre o log das chances, mas a tarefa que ela resolve é classificar.

Como ler os nomes sem decorar

Cada nome tem duas palavras, e cada uma responde uma pergunta:

  • A segunda palavra é O QUE O MODELO DISSE: Positivo = apontou fraude; Negativo = disse que está ok.
  • A primeira palavra diz SE ELE ACERTOU: Verdadeiro = acertou; Falso = errou.

Então Falso Negativo = o modelo disse "ok" (negativo) e errou: na verdade era fraude. E Falso Positivo = o modelo disse "fraude" e errou: era uma nota normal. Para saber o que era de verdade, inverta a segunda palavra quando a primeira for "Falso".

Pegadinha: o "negativo" do Falso Negativo O Falso Negativo não é um caso negativo. Ele é uma fraude real que o modelo chamou de negativa. Por isso as fraudes reais são VP + FN (a primeira linha) e as notas que o modelo apontou são VP + FP (a primeira coluna). É dessas duas somas que nascem o recall (revocação) e a precision (precisão).
Treino rápido 1

Um falso negativo corresponde a um caso que, na realidade, pertence à classe positiva, mas que o modelo classificou como negativo.

Isso. "Negativo" é o que o modelo disse; "Falso" diz que ele errou. Logo, na verdade era positivo (fraude).
O item está certo. Falso Negativo = o modelo disse negativo e errou, então o caso real era positivo.
Treino rápido 2

A soma dos falsos positivos com os verdadeiros positivos corresponde ao total de casos que, na realidade, pertencem à classe positiva.

Isso. VP + FP é tudo o que o modelo apontou (a coluna). Os positivos reais são VP + FN (a linha). No cenário: 40 + 60 = 100 apontadas, mas 40 + 10 = 50 fraudes reais.
O item está errado. VP + FP é o total que o modelo apontou como positivo (é o denominador da precision). Os positivos reais são VP + FN (o denominador do recall).

Precision · Precisão = VP / (VP + FP) → DOS QUE APONTEI, quantos eram fraude?

Recall · Revocação = VP / (VP + FN) (também chamado sensibilidade ou TPR, True Positive Rate · Taxa de Verdadeiros Positivos, TVP) → DAS FRAUDES QUE EXISTEM, quantas eu peguei?

F1-score · Medida F1 = 2·P·R / (P + R) → média harmônica, que só fica alta se as duas forem altas.

AUC-ROC (Area Under the Curve – Receiver Operating Characteristic · Área sob a Curva ROC – Característica de Operação do Receptor) → cruza a TPR com a FPR (False Positive Rate · Taxa de Falsos Positivos, TFP) e avalia o modelo em todos os limiares: é a probabilidade de uma fraude receber nota maior que uma nota normal. 0,5 é chute e 1 é perfeito.

Experimente: mexa nos números

O cenário inicial tem 1.000 notas, das quais 50 são fraudes (5%). O modelo apontou 100 notas e acertou 40 delas. Agora tente o modelo "preguiçoso" que nunca aponta fraude: coloque VP = 0, FP = 0, FN = 50, VN = 950.

O modelo preguiçoso tem 95% de accuracy (acurácia) e recall (revocação) zero: não pega nenhuma fraude e, mesmo assim, tem uma nota ótima. Por isso, com classes desbalanceadas, a acurácia engana, e você deve olhar precisão, recall e F1[2].

Exemplo resolvido: qual métrica priorizar?

A equipe de auditoria só consegue examinar 100 casos por mês. Cada alarme falso consome horas de um auditor.

→ Priorize a precisão. O alarme falso é o erro caro aqui. Se, ao contrário, deixar passar uma fraude grave for inaceitável (desvio na saúde, por exemplo), priorize o recall. As duas métricas disputam entre si: baixar o limiar aumenta o recall e diminui a precisão.

Pegadinha: precisão e recall trocados A banca adora dar a fórmula de um com o nome do outro. Fixe o denominador: a precisão divide pelo que o modelo apontou (VP + FP). O recall divide pelo que realmente é fraude (VP + FN).

Pratique: certo ou errado

Item 1

Por se tratar de um modelo de regressão, a regressão logística é indicada para prever valores contínuos, como o valor de um contrato.

Isso. Apesar do nome, a regressão logística é um modelo de classificação: gera uma probabilidade e, com um limiar, uma classe.
O item está errado. A regressão logística classifica. Para valor contínuo, use regressão linear, árvores de regressão e afins.
Item 2

Em uma base com 1% de fraudes, um classificador que sempre prevê "não fraude" alcança acurácia (accuracy) de 99%, embora seu recall (revocação) seja nulo.

Isso. Ele acerta todos os 99% normais e erra todas as fraudes: VP = 0, então o recall é 0.
O item está certo. Teste na calculadora: VP = 0, FN = 10, FP = 0, VN = 990.
Item 3

A precisão (precision) de um classificador é dada pela razão entre os verdadeiros positivos e o total de exemplos que realmente pertencem à classe positiva.

Isso. Dividir pelo total de positivos reais (VP + FN) é a definição de recall. A precisão divide pelo que foi apontado (VP + FP).
O item está errado: ele descreve o recall. A precisão é VP / (VP + FP).
Item 4

O coeficiente de determinação (R², coefficient of determination) pode assumir valores negativos quando o modelo apresenta desempenho inferior ao de prever sempre a média.

Isso. R² = 0 equivale a prever a média. Abaixo disso, o modelo é pior que esse baseline trivial.
O item está certo. Em dados de teste, o R² não fica preso entre 0 e 1 e pode ser negativo.
Item 5 · Caso prático

Após a redução do limiar de decisão, o recall (revocação) de um classificador de fraudes passou de 0,60 para 0,90. Nesse caso, a precisão (precision) tende a aumentar na mesma proporção, já que ambas as métricas variam no mesmo sentido.

Isso. Um limiar mais baixo aponta mais casos: pega mais fraudes (recall sobe), mas também mais notas normais (FP sobe), e a precisão tende a cair.
O item está errado. Precisão e recall costumam disputar entre si. Baixar o limiar aumenta os falsos positivos e derruba a precisão.
