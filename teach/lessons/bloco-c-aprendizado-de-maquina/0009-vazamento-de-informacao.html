Vazamento de informação (data leakage)

Vazamento é quando o modelo, durante o treino ou a avaliação, tem acesso a uma informação que não estaria disponível no momento real da previsão. O resultado é sempre o mesmo: uma nota boa demais na avaliação e um modelo que decepciona em produção[1].

Termos usados nesta lição
  • Padronizar: deixar cada coluna com média 0 e desvio 1, calculando (valor − média) / desvio-padrão. Serve para colunas em unidades diferentes (anos e reais) ficarem comparáveis.
  • Imputação: preencher valores que estão faltando, por exemplo com a média da coluna.
  • Pipeline: uma "esteira" que encadeia os passos (padronizar → selecionar colunas → treinar). Na validação cruzada, a esteira inteira é refeita dentro de cada fold.
  • Importância das variáveis: quanto cada coluna pesa nas decisões do modelo.

Exemplo resolvido 1: o jeito errado de fazer validação cruzada

O exemplo clássico de Hastie, Tibshirani e Friedman[2]: 50 amostras, 5.000 variáveis totalmente aleatórias e um rótulo também aleatório. A taxa de erro verdadeira de qualquer modelo é 50%, porque não há nada para aprender.

Jeito errado: escolher as 100 variáveis mais correlacionadas com o rótulo usando as 50 amostras e só depois fazer a validação cruzada. O erro estimado sai perto de 3%. As variáveis foram escolhidas olhando também os folds de validação, então a validação já "conhecia" a resposta.

Jeito certo: refazer a seleção de variáveis dentro de cada fold, só com os dados de treino daquele fold. O erro estimado volta para perto de 50%, que é a verdade.

Pegadinha: balancear antes de dividir Aplicar SMOTE (Synthetic Minority Over-sampling Technique · técnica de sobreamostragem sintética da minoria), ou qualquer reamostragem, na base inteira antes da divisão cria doentes sintéticos no treino que são "parentes" dos doentes do teste. A regra vale para todo pré-processamento: primeiro divide, depois ajusta só no treino e aplica no teste.

Como prevenir

  1. Divida primeiro. Separe o teste antes de qualquer análise ou transformação.
  2. Use pipelines. Coloque padronização, imputação e seleção dentro de um Pipeline, que é reajustado em cada fold da validação cruzada[3].
  3. Pergunte "quando?" para cada variável. Ela existiria no momento da previsão? Se só existe depois do fato, saia com ela.
  4. Respeite o tempo e os grupos. Validação temporal para dados com data; divisão por grupo para entidades repetidas (Lições 7 e 8).
  5. Desconfie do bom demais. Compare com o baseline (Lição 5) e olhe a importância das variáveis: uma única variável dominando tudo costuma ser vazamento.
Exemplo resolvido 2: a variável boa demais

Um modelo que prevê se uma pessoa tem diabetes atingiu AUC-ROC (área sob a curva ROC) de 0,99. A variável mais importante, de longe, era usa_insulina.

Diagnóstico: só usa insulina quem já foi diagnosticado com diabetes. A variável é uma consequência do alvo, não algo observável antes dele. É vazamento do alvo. Sem ela, a AUC cai para 0,78, que é o desempenho real.

Pratique: certo ou errado

Item 1

Para evitar vazamento de informação, recomenda-se padronizar as variáveis com média e desvio-padrão calculados sobre a base completa e, somente depois, separar os conjuntos de treino e teste.

Isso. O item descreve exatamente uma forma de vazamento. As estatísticas devem ser calculadas só no treino e aplicadas ao teste.
O item está errado. Calcular a padronização com a base inteira deixa o treino "ver" o teste. Primeiro divide, depois ajusta só no treino.
Item 2

Configura vazamento do alvo a inclusão, entre as variáveis preditoras, de informação que somente é registrada após a ocorrência do evento que se pretende prever.

Isso. Se a informação não existe no momento da previsão, o modelo está trapaceando.
O item está certo. É a definição de vazamento do alvo (target leakage).
Item 3

A seleção das variáveis mais correlacionadas com o rótulo pode ser feita com toda a base antes da validação cruzada, desde que o modelo seja treinado dentro de cada fold.

Isso. É o "jeito errado" clássico: a seleção já usou os rótulos da validação. Ela precisa ser refeita dentro de cada fold.
O item está errado. Selecionar variáveis com a base toda contamina a validação. No exemplo clássico, o erro estimado cai de 50% para cerca de 3%.
Item 4

Desempenho excepcionalmente alto na avaliação, aliado à predominância de uma única variável na importância do modelo, constitui indício de possível vazamento de informação.

Isso. É o sintoma clássico. A investigação começa perguntando se aquela variável existiria no momento da previsão.
O item está certo. Nota boa demais com uma variável dominante é o principal sinal de alerta de vazamento.
Item 5

A aplicação de técnicas de sobreamostragem, como o SMOTE, sobre toda a base antes da divisão entre treino e teste é prática recomendada, pois garante a mesma proporção de classes em ambos os conjuntos.

Isso. Os exemplos sintéticos nascem de vizinhos que podem estar no teste. A reamostragem vai só no treino. Para manter a proporção das classes, use divisão estratificada.
O item está errado. Sobreamostrar antes de dividir é vazamento. A proporção de classes se garante com estratificação, não com SMOTE na base toda.
