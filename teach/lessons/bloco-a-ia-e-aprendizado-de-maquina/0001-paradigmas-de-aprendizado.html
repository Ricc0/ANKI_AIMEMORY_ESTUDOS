Os quatro paradigmas de aprendizado

Supervisionado, não supervisionado, semissupervisionado e por reforço. Para não confundir os quatro, faça sempre a mesma pergunta: que informação o modelo recebe para aprender? Quase toda pegadinha de prova sobre esse tema sai daí[1].

Supervisionado: aprender com gabarito

Você treina com pares (X, y). X são as características (valor da nota, CNPJ, data, órgão) e y é a resposta certa ("fraude" ou "ok"). O modelo procura uma função f(X) ≈ y que erre pouco em dados que ele ainda não viu. Ir bem nos dados de treino não basta. É daí que nasce o sobreajuste (Lição 4).

O formato do y define a tarefa: se é um número, é regressão. Se é uma categoria, é classificação (Lição 2). O gargalo prático é o rótulo: alguém precisa dizer o que é fraude, e na CGU isso costuma ser um auditor gastando horas em cada caso.

Não supervisionado: estrutura sem gabarito

Só existe X. O modelo não prevê uma resposta. Ele descreve os dados: quais itens se parecem (agrupamento), quais variáveis carregam a mesma informação (redução de dimensionalidade) e quais pontos fogem do padrão (anomalias), como mostra a Lição 3. Não existe "acerto" objetivo: um especialista precisa interpretar se os grupos encontrados fazem sentido para o negócio.

Semissupervisionado: o meio-termo

Você tem poucos rotulados e muitos sem rótulo. A ideia é usar a forma dos dados sem rótulo para traçar a fronteira que os poucos rotulados não conseguem definir sozinhos[2].

Self-training: treina com os rotulados, prevê os demais, aceita como PSEUDO-RÓTULO só os casos de maior confiança, retreina e repete.

Propagação de rótulos: monta um grafo de vizinhança, e o rótulo "escorre" de um ponto para os vizinhos próximos.

O método só funciona se valerem três suposições:

  • Suavidade: pontos próximos têm o mesmo rótulo.
  • Cluster: a fronteira entre classes passa por regiões com poucos dados.
  • Variedade (manifold): os dados vivem numa estrutura de dimensão menor do que o número de variáveis.
Pegadinha: "mais dados sempre ajudam" Se a fraude não forma um grupo separado (fraudadores imitam notas normais, por exemplo), ou se os primeiros pseudo-rótulos saem errados, o modelo reforça o próprio erro a cada rodada. O resultado pode ficar pior do que treinar só com os rotulados.

Por reforço: aprender agindo

Não existe um conjunto de dados fixo. Um agente observa um estado, escolhe uma ação, o ambiente muda e devolve uma recompensa. O agente aprende uma política (qual ação tomar em cada estado) que maximize a recompensa acumulada, normalmente com um desconto γ sobre o futuro[3].

Rótulo × recompensa: por que o reforço não é supervisionado.
Rótulo (supervisionado)Recompensa (reforço)
Diz a resposta certa?Sim, para cada exemploNão, só dá uma nota para a ação tomada
Quando chega?Junto com o exemploMuitas vezes atrasada (só no fim do jogo)
De onde vêm os dados?Base fixaDa interação do agente com o ambiente
Três ideias que a banca cobra
  • Exploração × explotação: se o agente só repete o que já deu certo, nunca descobre algo melhor. Se só testa coisas novas, nunca aproveita o que aprendeu. Uma solução clássica é o ε-greedy, que explora ao acaso com probabilidade ε.
  • Atribuição de crédito: com recompensa atrasada, é difícil saber qual das 80 jogadas decidiu a partida.
  • Reward hacking: o agente otimiza a recompensa que você escreveu, não o objetivo que você queria[4]. Se você premia "processos encerrados", ele aprende a encerrar processos sem resolvê-los.
Pegadinha: reforço na auditoria O reforço precisa de muita interação ou de um simulador, e não dá para "testar" milhares de decisões reais de fiscalização. Para dados tabulares com histórico, o supervisionado costuma ser a escolha certa. Item que diga que o reforço é "a técnica indicada para classificar notas fiscais" tende a estar errado.

Pratique: certo ou errado

Item 1

O agrupamento (clustering) é uma técnica de aprendizado supervisionado, pois o algoritmo distribui os dados em classes.

Isso. O agrupamento é não supervisionado: os grupos são descobertos, não vêm rotulados. Quem usa classes já conhecidas é a classificação.
O item está errado. No agrupamento não há rótulo. Os grupos são descobertos pelo algoritmo. "Classes conhecidas no treino" é classificação.
Item 2

No aprendizado por reforço, a recompensa cumpre o mesmo papel do rótulo no aprendizado supervisionado, indicando ao agente a ação correta em cada estado.

Isso. A recompensa só avalia a ação tomada. Ela não diz qual seria a ação correta e pode chegar atrasada.
O item está errado. O rótulo traz a resposta certa. A recompensa só dá uma nota, sem gabarito.
Item 3

No aprendizado semissupervisionado, se as suposições de suavidade ou de cluster não se verificarem, o desempenho pode ser inferior ao obtido apenas com os dados rotulados.

Isso. Pseudo-rótulos errados se propagam, e o modelo reforça o próprio erro.
O item está certo. Os dados não rotulados só ajudam se as suposições valerem. Caso contrário, podem piorar o modelo.
Item 4

Reward hacking ocorre quando o agente maximiza a recompensa definida por meio de um atalho que não cumpre o objetivo pretendido pelo projetista.

Isso. É a recompensa mal especificada sendo explorada pelo agente.
O item está certo. É exatamente essa a definição de reward hacking (ou specification gaming).
Item 5 · Caso prático

Um órgão dispõe de 200 mil notas fiscais, das quais apenas 300 foram analisadas e rotuladas por auditores como "fraude" ou "regular". Nessa situação, o aprendizado por reforço é a abordagem mais indicada para aproveitar também as notas não rotuladas.

Isso. Não há agente nem ambiente interativo: há uma base fixa com poucos rótulos caros. Esse é o cenário típico do semissupervisionado.
O item está errado. Poucos rotulados e muitos sem rótulo, numa base fixa, apontam para o semissupervisionado. O reforço exige interação com um ambiente.
